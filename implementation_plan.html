Production-Ready JWT Security Implementation

Goal

Migrate from LocalStorage-based JWT storage to a production-ready security model using:

  1. HttpOnly Cookies for token storage (XSS protection)
  2. Refresh Token Pattern (short-lived access tokens)
  3. SameSite Cookies (CSRF protection)
  4. Secure flag (HTTPS only)

Current Security Issues

❌ LocalStorage Vulnerabilities:

  • XSS Attack Vector: Any JavaScript can access localStorage.getItem('access_token')
  • No HttpOnly Protection: Tokens exposed to all scripts
  • Long-lived Tokens: If stolen, valid until expiration

✅ Production Solution:

  • HttpOnly Cookies: JavaScript cannot access tokens
  • Short Access Tokens: 15 minutes (limits damage window)
  • Refresh Tokens: 7 days in HttpOnly cookie
  • SameSite=Strict: CSRF protection

Proposed Changes

Backend Changes

1. Update JWT Configuration

Add separate token generation methods for Access and Refresh tokens.

2. Update Authentication Controller

Update /login to set HttpOnly cookies instead of returning tokens in the body.

3. Add Refresh Token Endpoint

Create POST /refresh endpoint to issue new access tokens using the refresh cookie.

4. Update JWT Filter

Modify JwtAuthenticationFilter to read tokens from cookies instead of the Authorization header.

5. Update CORS Configuration

Enable allowCredentials(true) to allow cookies to be sent cross-origin (if needed, or same-origin).

6. Update Logout

Create /logout endpoint to clear the HttpOnly cookies.

Frontend Changes

1. Update Auth Service

Remove LocalStorage usage. Update login/logout methods to use withCredentials: true.

2. Add HTTP Interceptor

Create an AuthInterceptor to automatically handle 401 errors by calling the refresh endpoint and retrying the original request.

3. Add /me Endpoint (Backend)

Since the frontend no longer has the token to decode, add a /me endpoint to fetch current user details.
